# 全流程走读：一次真实用例从页面到 CI 的八站

> 配套代码：本仓库。所有片段均来自 TesterHome 实测（`spec/cases/testerhome/`）。
> 适用对象：新加入的工程师、需要理解框架的内网 AI、要迁移到 EMS 项目的同学。

---

## 0. 全景

```
[URL]
  │ ① snapshot
  ▼
.snap/home.json            ← 一次性原料（gitignore）
  │ ② 写用例（模型 / 人）
  ▼
spec/cases/*.json          ← 资产，唯一可手写入口
  │ ③ render
  ▼
tests/test_*.py            ← 生成物，禁止手改
  │ ④ pytest
  ▼
结果 / trace / 报错
  │ ⑤ 归因（四分类）
  ├── product_bug → 提单
  ├── case_error  → 回 ②
  ├── env         → 修环境
  └── flaky       → 隔离
        │ ⑥ 修正
        ▼
     ⑦ 闸门（render --check）
```

八站里，**只有第②站需要模型**。其余六站全部是确定性脚本或 pytest。

## 站 ① 环境自检

**输入**：环境变量 `BASE_URL`
**执行者**：`tools/preflight.py`
**输出**：5 行结论 + 退出码

```bash
python tools/preflight.py
```

```
PASS  python>=3.9    3.14
PASS  playwright 包   unknown
PASS  浏览器可启动     156.0.8078.4
PASS  BASE_URL 可达    https://testerhome.com -> HTTP 200
PASS  工作区可写        .snap/
```

**要点**：退出码 `0/1` 是给 agent 看的，文本是给人看的。没有这一站，agent 会在"浏览器没装"的环境里凭空编用例。

**失败会怎样**：`FAIL` 行直接指出缺什么（缺包 / 缺浏览器 / 站点不可达 / 不可写），不需要读堆栈。

## 站 ② 感知：把页面变成可引用的结构

**输入**：一个 URL
**执行者**：`tools/snapshot.py`（Playwright Python API）
**输出**：`.snap/<name>.json`

```bash
python tools/snapshot.py --url https://testerhome.com/ \
  --out .snap/home.json --wait "a[href='/topics']"
```

处理链：`goto` → 等元素可见 → 页面内执行 `COLLECT_JS` → 过滤语义节点 → 生成稳定 key。

输出片段：

```json
{
  "key": "link:社区",
  "role": "link",
  "name": "社区",
  "path": "div>div:nth-of-type(2)>ul>li>a"
}
```

本次实测：**194 个节点，26.6KB**（紧凑）/ 37KB（缩进）。

**要点**

1. `key` 优先级：`tid:<data-testid>` > `<role>:<name>`，重名追加 `#2`。**绝不用 DOM 序号**——序号每次快照都会变，模型上一轮记的引用下一轮就错位。
2. `path` 采了但**禁止用于定位**。它只是调试信息；拿 DOM 结构当契约，页面一改全废。
3. 增量：加 `--diff .snap/上一次.json` 只输出变化，避免每次重喂全量。

## 站 ③ 写用例（唯一需要模型的环节）

**输入**：快照 + 需求 / 风险判断
**执行者**：模型或人
**输出**：`spec/cases/testerhome/th-002.json`

```json
{
  "id": "TH-002",
  "title": "顶部导航「社区」跳转到帖子列表",
  "requirement": "TH-NAV-TOPICS",
  "priority": "P1",
  "risk": "主导航失效，用户无法进入社区列表",
  "steps": [
    { "action": "goto", "url": "/" },
    { "action": "click", "target": { "role": "link", "name": "社区", "exact": true } },
    { "action": "expectUrl", "contains": "/topics" },
    { "action": "expect", "target": { "role": "link", "name": "社区", "exact": true },
      "assertion": { "type": "visible" } }
  ]
}
```

**三条规矩**

- 不许出现 CSS / XPath。
- `exact: true` 不是装饰：`社区` 不加 exact 会同时命中 `社区学堂`。
- `risk` 写不出来，说明这条用例不该生成。

## 站 ④ 渲染：JSON → 代码

**输入**：`spec/cases/testerhome/th-002.json`
**执行者**：`tools/render.py`
**输出**：`tests/test_th_002.py`

```bash
python tools/render.py --all spec/cases/testerhome
```

```python
# AUTO-GENERATED by tools/render.py —— 请勿手改；改 spec/cases/testerhome/th-002.json 后重新生成
# case: TH-002  requirement: TH-NAV-TOPICS  priority: P1
import re

from playwright.sync_api import Page, expect

def test_th_002(page: Page, base_url: str) -> None:
    """TH-002 顶部导航「社区」跳转到帖子列表"""
    page.goto(base_url + "/")
    page.get_by_role("link", name="社区", exact=True).click()
    expect(page).to_have_url(re.compile("/topics"))
    expect(page.get_by_role("link", name="社区", exact=True)).to_be_visible()
```

**映射表**

| JSON | Python |
|---|---|
| `goto: "/"` | `page.goto(base_url + "/")` |
| `role + name + exact` | `get_by_role(name=..., exact=True)` |
| `testid` | `get_by_test_id()` |
| `href` | `page.locator("a[href=...]", has_text=...)` |
| `label + exact` | `get_by_label(..., exact=True)` |
| `expectUrl.contains` | `to_have_url(re.compile(...))` |
| `assertion.type=count` | `to_have_count()` |
| `captureNetwork` + `expectNetwork` | `with page.expect_response(...)` + `assert ...status` |

`import re` 是按需插入的：只有用了 URL 正则才会出现。

## 站 ⑤ 执行

```bash
set BASE_URL=https://testerhome.com
python -m pytest tests -k th_ -q
```

**输出**：`5 passed in 26.03s`

**失败时长什么样**（TH-003 首次运行的真实报错）：

```
playwright._impl._errors.Error: Locator.click: Error: strict mode violation:
get_by_role("link", name="问答", exact=True) resolved to 2 elements:
  1) <a class="nav-link" href="/questions">问答</a>
  2) <a title="问答" data-id="20" href="/topics/node20">问答</a>
```

**关键认知**：这不是框架坏了，而是框架在正确报告"定位有歧义"。strict mode 是保险丝，不是故障。

## 站 ⑥ 归因（四分类）

**输入**：失败信息 + 快照
**执行者**：人或 verifier agent
**输出**：`triage.json`（当前为人工判断，工具未实现）

| 分类 | 判断依据 | 归宿 |
|---|---|---|
| `product_bug` | 元素存在、操作成功、结果不对 | 提单 |
| `case_error` | 定位歧义、断言写错、数据不对 | **回站 ③ 改 JSON** |
| `env` | 404、超时、证书、登录失效 | 修环境，不改用例 |
| `flaky` | 重跑 3 次结果不一致 | 隔离 + 标记 |

TH-003 属于 `case_error`：页面上真有两个"问答"链接，是用例没消歧。

## 站 ⑦ 修正与回流（两条完全不同的路）

### 路径 A：用例错 → 改 JSON

```diff
- { "action": "click", "target": { "role": "link", "name": "问答", "exact": true } },
+ { "action": "click", "target": { "role": "link", "name": "问答", "exact": true,
+                                  "href": "/questions" } },
```

重渲染后生成：

```python
page.locator("a[href=\"/questions\"]", has_text="问答").click()
```

### 路径 B：框架 bug → 改 renderer

实测遇到两个：

1. `expectUrl.contains` 生成了 `toHaveURL(//topics/)` —— 非法正则
2. `get_by_label("手机号")` 命中表单与输入框 —— label 也需要 `exact`

改 `render.py` 后**必须全量重渲染**，因为所有生成物都受影响。

### 铁律

**两条路绝不能混。**

- 把框架 bug 当用例错 → 掩盖问题
- 把用例错当框架 bug → 污染所有用例

## 站 ⑧ 闸门与固化

```bash
python tools/render.py --all spec/cases --check
# [check] ok tests/test_th_001.py ... 全部一致：tests/ 没有被手改
```

生成物一旦被手改，就再也说不清"线上跑的是不是从 JSON 生成的"。`--check` 重渲染到内存比对，不一致退出码 1，CI 拦住。

## 产物地图

| 产物 | 性质 | 能否手改 | 进 git |
|---|---|---|---|
| `.snap/*.json` | 一次性原料 | 可以 | 否 |
| `spec/cases/*.json` | **资产** | 可以，唯一入口 | 是 |

| `test-results/` | 失败证据 | — | 否 |

## 换到 EMS 项目，每一站变成什么

| 站 | 当前框架 | EMS 项目 |
|---|---|---|
| ① 自检 | preflight | 相同 |
| ② 感知 | 快照页面 | **`index_pom.py` 扫仓库**（POM 已是人工整理的契约） |
| ③ 用例 | 写 DOM 语义 | **写 POM 调用**：`{"action":"call","page":"AlarmCenterPage","method":"filter_by_level"}` |
| ④ 渲染 | 生成内联定位 | **生成对既有 POM 的调用 + fixture 注入** |
| ⑤ 执行 | `pytest -k th_` | 完全相同 |
| ⑥ 归因 | 四分类 | 增加 `pom_gap`（需要补 POM） |
| ⑦ 修正 | 改 JSON / 改 renderer | 改 JSON / **改 POM 补丁** |
| ⑧ 闸门 | `--check` | 增加 `git diff --name-only` 边界检查 |

**变化最大的是 ② 和 ③**：有 POM 的团队不需要"探索页面"，因为 POM 就是整理过的页面契约；用例也不再描述 DOM，而是描述业务动作。

## 常见失败对照

| 现象 | 通常属于 | 处理 |
|---|---|---|
| `strict mode violation` | case_error | 加 `exact` / `href` / `testid`，不要用 `.first()` |
| 元素找不到但页面能看到 | case_error 或 a11y 缺失 | 先看快照里有没有；没有就让前端补语义 |
| 生成代码语法错误 | 框架 bug | 改 renderer，全量重渲染 |
| 测试时绿时红 | flaky | 接口 mock + 语义等待，禁止 sleep |
| `--check` 报 DIRTY | 有人手改了 `tests/` | 回滚，改 JSON 重渲染 |
