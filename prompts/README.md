# 把设计文档喂给内网 AI 的两轮方案

目标：让内网 AI 读懂 `docs/DESIGN-PHILOSOPHY.md`，对照评估你们现有框架，而不是照搬。

```
准备 evidence.md
      ↓
第 1 轮  round1.md   只校准理解 → 产出「规则卡」
      ↓ 验收（5 条）
第 2 轮  round2.md   打分 + 改造建议（新会话）
      ↓ 验收（3 条）
```

分两轮的原因：

1. 第一次只读文档，**防止它把"生成对 POM 的调用"读成"用 AI 写 Playwright 脚本"**。
2. 第一轮的规则卡是压缩产物，第二轮不再需要全文，**token 省一半**。

## 第 0 步：生成证据包

```bash
python tools/collect_evidence.py --root D:\work\ems-autotest --out evidence.md
```

目标体积 **≤ 15KB**。超了就调小 `--max-lines` 或 `--max-tests`。

## 第 1 轮验收

| 检查 | 通过标准 | 不通过怎么办 |
|---|---|---|
| 规则句式 | ≥8 条是"禁止/必须"句式 | 「第 X 条不是可执行规则，改写成祈使句」 |
| 三条不变量 | 覆盖：不写选择器 / 不碰生成物 / LLM 不进 CI | 「重读 §2.3，补齐并说明为何漏掉」 |
| 反例具体 | 说清后果，不是同义反复 | 「用一句话说明会导致什么线上问题」 |
| 证据真实 | 引用文件名在 evidence.md 中真实存在 | 抽查 2 个，错一个就重跑 |
| 存疑有理由 | 3 条都有具体依据 | 「指出文档中哪一节的哪个论断你不同意」 |

**三条不变量漏一条，本轮作废重跑。** 那是文档骨架，漏了说明它只是在做摘要。

## 第 2 轮验收

| 检查 | 通过标准 | 不通过怎么办 |
|---|---|---|
| 证据可核 | 抽查 3 条 `evidence_ours`，文件存在、行号对得上 | 有一条假，整份作废——它会系统性编造 |
| 不凑建议 | 我方 3 分 / 对方 0 分的项必须写"无需改造" | 「第 N 项我方 3 分对方 0 分，为什么还建议改？」 |
| 建议可执行 | 每条都有能在内网跑通的验证命令 | 缺验证的退回重写 |

## 三个高频翻车

| 现象 | 原因 | 补救 |
|---|---|---|
| 十条规则全是名词短语 | 把提炼当成摘要 | 「每条以"禁止"或"必须"开头」 |
| 十项全打 2 分 | 没有锚点或不敢判断 | 重贴锚点，加一句「不允许超过 3 个相同分值」 |
| 建议里出现"引入 codegen/重写测试" | 没读懂 §9.2 | 「重读并回答：有 POM 的框架里，生成器应该生成什么？」 |

## 上下文不够（<32k）怎么办

第 1 轮会被截断，症状是：规则只有 5–6 条、表格中途断掉、JSON 不完整。

改成三段式：

1. 喂 §0–§5，输出前 6 条规则
2. 喂 §6–§15，补后 4 条 + 存疑
3. 合并后再进第 2 轮

## 提醒

这套提示词的设计目标之一是**让 AI 有资格说"你们不用改"**。

如果它给出"全面引入 JSON 中间层"这类建议，多半没读懂 §9.2——
对已有 POM 的框架，正确做法是生成对 POM 的调用，而不是另起一套。
