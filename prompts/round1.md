# 第一轮：校准理解

你将读到一份外部框架设计文档，以及我们仓库的证据包。

## 输入

1. 文档：`docs/DESIGN-PHILOSOPHY.md` 全文（约 550 行）
2. 证据包：`evidence.md`

## 本轮任务

只做一件事：**证明你读懂了文档，并对照我们的现状。**

不要给改造建议，不要打分，不要评价优劣——下一轮才做。

## 步骤

1. 阅读文档全文。
2. 提炼 10 条可执行规则。每条必须写成"禁止/必须"的句式，不能是名词短语。
   - 反例：❌「语义定位」
   - 正例：✅「禁止在用例里出现 CSS/XPath 选择器」
3. 每条规则给出：
   - 一个反例及其后果（这样做会出现什么问题）
   - 我们当前是否满足：`是` / `否` / `部分` / `no-evidence`
   - 满足或部分满足的，必须引用 `evidence.md` 里出现过的文件名
4. 指出文档中你**不认同或存疑**的 3 条，说明具体理由。

## 输出格式（严格遵守）

**A. 规则表**

| # | 规则 | 反例后果 | 我方现状 | 证据 |
|---|---|---|---|---|

**B. JSON**（字段固定，必须可被脚本解析）

```json
{"rules":[{"id":1,"rule":"...","anti":"...","ours":"yes|no|partial|no-evidence","evidence":"..."}]}
```

**C. 存疑清单**（3 条，每条不超过 60 字）

## 约束

- 总长不超过 1200 字。
- 不要加客套话、不要复述文档结构。
- 判断不了就写 `no-evidence`，不要猜。
